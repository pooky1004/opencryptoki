# Debug App 사용자 매뉴얼 (상세)

Token NCMP **Debug App**(공유메모리 뷰어)의 화면·버튼·필드와 각 항목의 의미를
처음 쓰는 사람도 따라 할 수 있도록 설명한다. 설치·실행·시스템 설정은
[`debugapp-deployment.md`](debugapp-deployment.md), 설계는
[`debugapp-design.md`](debugapp-design.md).

이 도구는 **읽기 전용**이다. ncmpd가 쓰는 공유 메모리를 들여다보기만 하며, 토큰에
명령을 보내지 않는다(그건 Test App의 역할).

---

## 0. 화면 구성

```
┌───────────────────────────── 헤더 ─────────────────────────────┐
│ 제목 [☀️테마][서버토큰][☑자동새로고침][주기 1초][재연결] ● SHM 연결됨 │
├──────────────────────────── 상태 바 ───────────────────────────┤
│ SHM /ncmpd_shm  magic 0x4E434D50  version 2  slotCount 256 … │
├───────────────┬────────────────────────────────────────────────┤
│ 슬롯(공유메모리)│  Slot N 상세                                   │
│  Slot 0 ONLINE │   슬롯 상태 / 통계 / 토큰 신원 / 명령 링 /        │
│                │   comm↔HSM 마지막 TX·RX(raw+parsed)              │
├───────────────┴────────────────────────────────────────────────┤
│ 로그                                                            │
└──────────────────────────────────────────────────────────────────┘
```

**사용 순서**: ncmpd가 실행 중이면 자동으로 연결되어 슬롯이 보인다. 왼쪽에서
슬롯을 클릭하면 오른쪽에 그 슬롯의 공유메모리 내용이 표시되고, **기본 1초마다
자동 갱신**된다(헤더에서 주기 조절·끄기 가능).

## 1. 헤더

| 요소 | 기능 | 비고 |
|------|------|------|
| **☀️/🌙 테마** | 밝은·어두운 테마 전환 | 선택이 브라우저에 저장됨 |
| **서버 토큰** | API 인증 베어러 토큰 | 서버가 `NCMP_DBG_TOKEN`을 설정한 경우에만 입력(동일 값). 아니면 비움 |
| **자동 새로고침** | 체크 시 주기마다 상태·슬롯·상세를 다시 읽음 | 끄면 수동(클릭 시에만) |
| **주기(초)** | 자동 새로고침 간격(기본 **1초**, 1~60) | 값을 바꾸면 즉시 반영 |
| **재연결** | SHM을 떼었다 다시 붙임 | ncmpd를 재시작했거나 연결이 끊긴 뒤 사용 |
| **● 램프 / 문구** | ncmpd SHM 연결 여부 | 초록=연결(attach됨), 회색=미연결 |

## 2. 상태 바 (SHM 헤더)

ncmpd가 만든 공유 메모리의 전역 헤더(`NCMP_ShmHeader`)를 보여준다.

- **SHM**: 공유 메모리 객체 이름(`/ncmpd_shm`).
- **magic**: 서명(`0x4E434D50` = "NCMP"). 값이 맞아야 올바른 영역이다.
- **version**: SHM 레이아웃 버전.
- **slotCount**: 전체 슬롯 수(`PKCS11_MAX_SLOT_COUNT`, 최대 256). 대부분 비어 있음.
- **totalSize**: 공유 메모리 전체 크기(바이트).
- **slotMask**: 온라인 슬롯 비트마스크(핸드셰이크로 받은 값, 하위 32비트).
- **sock**: ncmpd 제어 소켓 경로.

---

## 3. 왼쪽: 슬롯 목록 (실재 슬롯)

- **무엇인가**: 전체 슬롯 중 **상태가 ABSENT가 아닌**(ONLINE/FAULTED), 즉 데몬이
  실제로 올린 슬롯만 나열한다. 대부분 토큰 1개면 `Slot 0` 하나다.
- 각 항목: `Slot N` + **상태 뱃지**(ONLINE 초록 / FAULTED 빨강 / ABSENT 회색),
  그 아래에 토큰 라벨(식별됐을 때) · 현재 in-flight · 누적 전송 수.
- **클릭**하면 오른쪽에 상세가 뜬다.
- 맨 아래 `표시 N · 전체 슬롯 256`으로 전체 대비 표시 개수를 안내한다.
- 비어 있으면: 토큰이 연결되지 않았거나 데몬이 아직 슬롯을 올리지 않은 것.

---

## 4. 오른쪽: 슬롯 상세 (슬롯별 공유메모리)

선택한 슬롯의 `NCMP_Slot` 구조체를 범주별로 보여준다.

### 4.1 슬롯 상태
- **state**: `ONLINE`(토큰 있고 comm thread 동작), `ABSENT`(없음),
  `FAULTED`(USB/토큰 오류, 복구 대기).
- **boundCkSlot**: 이 물리 슬롯을 claim한 CK 슬롯 id. `-1`이면 아직 미바인딩.
- **curSessions**: 현재 열린 세션 수(`sess_lock` 보호).
- **maxInflight**: 동시에 토큰에 보낼 수 있는 명령 상한(디바이스 컨테이너 수).
- **bufPool.off/len**: 이 슬롯의 스크래치 버퍼 풀 위치/크기(요청·응답 버퍼 영역).

### 4.2 통계 (comm thread가 갱신)
- **in_flight_cnt**: 지금 토큰 내부에 있는(응답 대기 중) 명령 수.
- **stats_max_in_flight**: 그동안의 in-flight 최고치.
- **stats_total_sent_cmds**: 토큰으로 보낸 누적 명령 수.
- 쓰임: 부하·동시성·정체를 관찰. 명령을 보낼수록 total_sent가 증가하고,
  응답이 밀리면 in_flight가 올라간다.

### 4.3 토큰 신원 (`NCMP_TokenIdentity`)
데몬이 부팅 시 `NCMP_CMD_VD_TOKEN_INFO`로 채운다.
- **valid**: 식별 성공 여부(1=성공). **0이면 아래 필드는 비어 있다.**
- **label / serial / manufacturer / model**: 토큰 식별 정보.
- **hwVersion / fwVersion / flags**: 하드웨어·펌웨어 버전, 벤더 플래그.
- 참고: 펌웨어가 없는(부트로더) 보드는 `valid=0`에 라벨 등이 공백이다. 이는
  정상적인 "미식별" 표시이며, 전송·슬롯 온라인과는 별개다.

### 4.4 명령 링 (MPSC queue, depth 32)
슬롯의 명령 큐(`NCMP_QEntry ring[32]`) 상태.
- **히스토그램**: 각 상태의 엔트리 수.
  - `FREE` 비어 있음 → `CLAIMED` 생산자가 확보 → `POSTED` 게시됨 →
    `SENT` 토큰으로 전송됨 → `DONE` 응답 완료 → `FREE`로 복귀.
    타임아웃 시 `SENT → ABANDONED`.
  - 평소(유휴)에는 `FREE 32`가 정상. 명령이 몰리면 CLAIMED/POSTED/SENT가 보인다.
- **비-FREE 엔트리 표**: 활성 엔트리의 `idx`(링 인덱스), `state`, `ownerSess`
  (요청한 세션 id), `seq`(요청/응답 상관 id), `reqLen`/`rspLen`(요청·응답
  바이트 길이). 정체·누수·특정 세션의 대기 명령을 짚을 때 유용.

### 4.5 comm ↔ HSM 마지막 메시지 (TX/RX raw + parsed)
comm_thread가 이 슬롯에서 HSM(토큰)과 **마지막으로 주고받은** 프레임을 보여준다.
- **송신(TX → HSM)**: comm_thread가 토큰으로 보낸 마지막 프레임(세션 id 변환·컨텍스트
  치환이 **적용된 실제 와이어 바이트**).
- **수신(RX ← HSM)**: 토큰에서 받은 마지막 프레임(원시).
- 각각 **raw(Hex, 16바이트 정렬)** 와 **parsed**(frame_len·session_id·sequence_id·
  command_id(+CI 이름)·ack(+CKR 이름)·payload_len·param[i])로 표시된다.
- **파라미터 하나가 1024바이트를 초과하면 hex는 1024바이트까지만** 보여준다(실제
  길이는 `len`에 그대로, 표시 바이트 수는 `표시 NB, 잘림`으로 함께 표기). 프레임
  전체 캡처는 최대 4KB(`N/M B (truncated)`).
- **송신(TX)은 전송이 실패해도 기록**된다 — 토큰이 응답하지 않는 상태에서도
  comm_thread가 무엇을 보냈는지 확인할 수 있다(수신은 응답이 와야 채워짐).
- 데몬은 **부팅 시 토큰 정보를 조회하지 않는다**(세션 없이 조회하던 부팅 probe는
  비활성화됨). 따라서 기동 직후에는 송신/수신이 **비어 있고**, 앱이 첫 명령을 보낸
  뒤부터 그 명령의 TX(및 응답 시 RX)가 표시된다.
- 슬롯 상세는 자동 새로고침(기본 1초)에 포함되므로, 명령이 오갈 때마다 최신 교환이
  갱신된다. (읽기 전용 — 이 앱은 명령을 보내지 않는다.)

## 6. 자주 쓰는 사용법

### 6.1 데몬·슬롯이 살아 있는지 빠르게 확인
1. 페이지를 연다 → 헤더 램프가 **초록**이면 ncmpd SHM 연결됨.
2. 상태 바의 magic/version이 정상인지 확인.
3. 왼쪽에 `Slot 0 ONLINE`이 보이면 토큰 슬롯이 올라와 있는 것.

### 6.2 토큰이 식별됐는지 확인
- 슬롯 선택 → **토큰 신원** 카드의 `valid`가 1이고 label/serial이 채워졌는지 본다.
- `valid=0`이면 펌웨어 미적재/식별 실패(전송은 정상일 수 있음).

### 6.3 명령 정체/동시성 관찰
- Test App 등으로 토큰에 부하를 주는 동안 이 화면을 **자동 새로고침**으로 열어
  두고, **통계**(in_flight / total_sent)와 **명령 링** 히스토그램의 변화를 본다.
- 특정 엔트리가 오래 `SENT`에 머물거나 `ABANDONED`가 쌓이면 타임아웃/정체 신호.

### 6.4 ncmpd 재시작 후
- 데몬을 다시 띄웠으면 **재연결**을 눌러 새 SHM에 붙는다.

## 7. 실 타겟 시험 결과(요약)

실 FX3(`04b4:00f1`, 부트로더)로 ncmpd(`--transport real`)를 띄우고 Debug App으로
확인한 결과:
- **연결/헤더 정상**: `connected=true`, magic `0x4E434D50`, version 2,
  slotMask `0x1`.
- **슬롯 0 ONLINE** 표시, 명령 링 `FREE 32`(유휴), 통계 0.
- **토큰 신원**: 보드 상태에 따라 공백(부트로더) 또는 `MPF300TS Development`/
  `UNPROVISIONED`(펌웨어 적재). SHM의 실제 상태를 있는 그대로 반영.
- **자동 새로고침(기본 1초)**: 상태·슬롯·상세가 주기적으로 갱신됨을 확인. 토큰에
  명령을 보내는 CI 송수신 기능은 제거되어, 이 앱은 순수 **읽기 전용 SHM 뷰어**다.

## 8. 용어
- **SHM(공유 메모리)**: ncmpd가 만들어 STDLL·도구가 함께 보는 메모리 영역.
- **슬롯(Slot)**: 물리 토큰 자리. 각 슬롯이 상태·토큰신원·통계·명령 링을 가진다.
- **명령 링(MPSC queue)**: 여러 생산자가 넣고 슬롯의 comm thread가 소비하는 큐.
- **in-flight**: 토큰에 보냈지만 아직 응답을 못 받은 명령.
- **conn thread**: ncmpd의 접속/핸드셰이크 담당 스레드(Debug App이 여기와 통신).
