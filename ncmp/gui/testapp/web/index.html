    종류pidapp_sidhsm_sid

    "새 세션"은 R/W 속성으로 C_OpenSession을 호출해 토큰까지 명령을 보냅니다. ncmpd가 토큰 OPEN으로 hsm_sid를 할당·매핑합니다.

      AES-CTR (암·복호화)
      
          
      선택한 세션으로 사용자 키를 C_CreateObject → C_EncryptInit(CKM_AES_CTR)
            → C_Encrypt로 처리합니다. CTR은 암·복호화가 동일 연산입니다. 입력 ≤ 3968바이트.

      멀티파트 digest (대용량 · Init / Update×N / Final)
      
          
      64KB 이상 데이터를 여러 번의 C_DigestUpdate로 나눠 처리합니다.
            데이터는 직접 입력(위 "해시" 카드, 단발)하거나, 크기를 지정해 Hex 시험파일
            (64바이트/줄)을 만들거나, 기존 시험 파일을 선택해 사용합니다.

      AES-GCM · 인증 암호화
      
          
      선택한 세션으로 사용자 키를 C_CreateObject → C_EncryptInit(CKM_AES_GCM)
            → C_Encrypt/C_Decrypt로 처리합니다. 암호화 출력은 암호문+태그, 복호화 입력은 암호문+태그입니다.

      ML-DSA / ML-KEM (PQC)
      
          
      이 웹앱이 로드하는 standalone facade(mode-2)에는 ML-DSA/ML-KEM
            연산이 구현되어 있지 않습니다(스텁). 광고 메커니즘 목록은 "세션 관리"의
            토큰 정보 조회에서 확인할 수 있습니다. PQC 전체 기능은 opencryptoki full 빌드의
            mode-1 STDLL에서 제공됩니다(ncmp_specific.c).

      CI(Command Interface) 단위로 실 타겟에 프레임을 직접 보내고 받습니다. 송신/수신 메시지를 raw(Hex)와 parsed 형태로 디버깅 창에 동시 출력합니다.
      
          
      
            
            
            
            
            
            
          
      
          
      
            
      CI별 입력 파라미터(Hex, 공백 허용, 비우면 생략). 예: 10000000 = little-endian u32 값 16
      
            
      
          
      
          
      디버깅 창 — 송신(TX)/수신(RX)을 raw(Hex) + parsed 동시 출력
      
          
      
        
      
      
      

      
      
      
        
      
          
      
            테스트 파일 생성 (init/update/final 시험은 데이터 ≥ 64KB 필요)
            
      
              
              
              
              
              
            
      
            
      반복 가능한 PRNG 패턴으로 채웁니다. 생성 시 SW SHA-256(참조)을 함께 표시합니다.
      
          
      

          
      
            실 타겟 ↔ SW 결과 비교 (토큰이 정확히 동작하는지 확인)
            
      
              
            
      
            
      
              
              
              
              
              
            
      
            
      
              비교는 세션이 필요합니다(세션 관리에서 열기). 토큰(실 FX3)의 multipart
              (init/update/final) 결과와 호스트의 OpenSSL 계산 결과를 대조해
              일치(MATCH) 여부로 정확성을 판정합니다. mock 토큰은 실제 해시가
              아니므로 MISMATCH가 정상입니다.
